0 · PrinciplesThe rules every Copilot component follows (from the canvas notes, kept and tightened)
Rules
RULE
One card per requestEach request gets one AI card that changes state in place: Understood → (Question) → Building → Applied. No plans, summaries or closing essays.
Ask littleOnly ask what changes when trades fire. Max 2 questions, always as tappable options with one Suggested. Small details Copilot decides itself and shows as dashed “assumed” chips you can change.
Add, then undoAdding to the canvas happens straight away with Undo. Anything that changes or removes a block you made is shown first and needs Apply.
Proof, not promisesEvery build ends with signal counts and “Check on chart”. The chart is one tap away, never forced.
Decide fit before buildingFits / Partly fits / Code only is decided before anything is placed, never discovered as an error.
Quiet retriesRetries are silent. Only a final failure shows: one line, what was kept, two ways forward.
Vague in, choices outA vague prompt gets 3 directions as taps. Copilot never invents a strategy or promises profit.
Colour and changes
DECISION
Violet = made by CopilotOnly the ✦ mark, Copilot-made blocks, ghost blocks being placed, and highlighted code lines. Not the input box, not progress bars, not buttons.
Activity = blueProgress, spinners and the focus ring use the product blue, like everywhere else.
Card actions = outlined blueCheck on chart, Apply changes, Build anyway. The page keeps its one filled-blue button.
Canvas = the builder kitBlocks, All of / Any of nodes and editor rings come from the canvas builder kit. No AND pills.
